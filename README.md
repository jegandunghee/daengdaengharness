## 7. 트러블 슈팅
문제 1. GitHub 소스 병합(merge) 과정에서 충돌 발생으로 구현 일정 지연
상황: 팀 프로젝트 진행 중 각자 작업한 브랜치를 병합하는 과정에서
    동일한 파일을 여러 명이 동시에 수정하면서 merge 충돌이 발생했다.
    충돌을 해결하는 데 시간이 소요되어 일부 기능 반영이 계획보다 늦어졌다. 
해결: 충돌이 발생한 파일에서 Git 충돌 마커를 기준으로
    각 변경 사항을 하나씩 확인하며 필요한 코드만 선별해 병합했다.
    기능 정상 동작 여부를 직접 확인한 뒤 다시 빌드하여 문제를 해결했다.
과정: 충돌 해결 과정에서 단순히 "충돌을 없애는 것"이 아니라
    각 코드가 왜 추가되었는지 의도를 이해하며 정리했다.
    이를 통해 Git 병합 구조와 충돌 해결 흐름을 실제로 경험할 수 있었다.
향후 계획 : 기능 단위로 커밋을 나누고, 역할 분담 시 페이지 별 분담이 아닌  
    기능별로 나누는 것이 병합과 기능 구현에 더 적합함을 배웠다. 
    작업 전 최신 브랜치를 PULL한 뒤 작업하는 협업 규칙등이 중요함을 알게되었고,
    앞으로도 현업 프로젝트에서는 소스 관리 규칙을 먼저 지정하고 
    충돌을 최소화하는 방향으로 작업할 계획이다.
